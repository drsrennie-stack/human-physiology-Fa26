## 1. One page was dead, and had been for a while

`competency-recall.html` opened, threw away its own content, and printed:

> The competency file did not load. Check that `bio005-competencies.js` sits next to this page.

The file was sitting right next to it and loading fine. The page reads `window.BIO005`. `bio005-competencies.js` exports `BIO005_COMPETENCIES`, `BIO005_MODULES` and `BIO005_META`, and never exported `window.BIO005` at all. The name simply did not exist, so the guard fired every time.

`mastery-physio-os-standalone.html` had quietly built that same view privately, inside itself, which is why the OS worked and the recall page did not.

**Fixed** by exporting the view once, from `bio005-competencies.js`, so every consumer gets it. Verified: 6 tabs, 6 panels, 137 competencies, 5 modules, 15 weeks, 13 general areas, 0 JS errors, 0 axe violations.

## 2. Accessibility: 34 pages, now 0 violations

Ran axe-core across every HTML file in the repo, WCAG 2.0 A/AA, 2.1 A/AA and 2.2 AA. Ten pages were failing.

| What | Where | Was | Now |
|---|---|---|---|
| Maroon text on navy | `physiology-course-home.html`, 15 elements: eyebrows, headline accents, pull quote, logo accent, footer headers and byline, problem numerals | 1.98:1 and 1.30:1, unreadable | `#D0705F` at 5.58:1 for headline sizes, `#EDB0A4` at 10.28:1 for small text |
| Gold prerequisite box header | `before-you-start.html` and all six unit pages | 4.01:1 and 4.39:1, below the AA floor | box darkened to `#63481A`, now 8.49:1 |
| `svg role="img"` holding focusable brackets | `pulmonary-function-lab.html` | invalid, an image cannot contain controls | `role="group"`, label preserved |
| `aria-controls` pointing at nothing | `competency-recall.html` | consequence of the dead page above | resolved by the fix in section 1 |

The maroon-on-navy fix needed three-class selectors. A two-class override lost on specificity to the rule that caused the problem, and silently did nothing. Worth knowing before anyone tries to fix it a second time.

## 3. Lora, italics and serifs, gone

You had them because `palettes.md` tells you to. The PRIMARY type scale says "Lora italic: usage instructions, body emphasis," so every file using it was built correctly against your own spec. Your standing rule and your palette document disagree. `BRAND-MIGRATION.md` flagged that in August and never got an answer.

`fix-lora-italics.py` cleared the code side, 29 files:

- the `--serif` token, which was Lora
- 9 font stacks naming Lora
- **42** `font-family:var(--font-serif,Georgia),serif` declarations, where the token is never defined so it quietly landed on Georgia
- a stray Fraunces webfont import
- every `font-style:italic`
- Lora out of the Google Fonts URLs, one less font file per page
- an `em,i,cite,dfn,var,address{font-style:normal}` reset in each HTML file, so browser-default italics cannot creep back

Verified across seven spot-checked pages: no serif, no italic, no Lora in any rendered text.

**Still yours to do:** delete that line from `palettes.md`, or the next file rebuilds the problem.
